# 手机端 IMU 展示迭代计划

## 1. 项目目标

基于桌面版 `IMU_ui/trajectory_monitor` 的核心能力，在 Android 手机端实现一个更轻量的 IMU 展示应用。

手机端不照搬桌面端的三栏复杂显控界面，而是采用底部导航组织核心功能：

```text
轨迹 | 地图 | 设备
```

核心目标：

- 现场快速查看 IMU 是否正常运行。
- 实时展示轨迹线、当前位置、航向、速度、距离和姿态。
- 提供必要的 TCP 连接、协议选择、工作模式和日志查看。
- 第一阶段优先保证可运行、可观察、可调试，不做过度复杂配置。

## 2. 总体界面结构

### 2.1 底部导航

```text
┌─────────────────────────────┐
│ 当前页面内容                  │
│                             │
│                             │
├─────────────────────────────┤
│    轨迹      地图      设备    │
└─────────────────────────────┘
```

### 2.2 轨迹页

轨迹页是默认首页，负责运行态观察。

内容组成：

- 顶部状态条
- 轨迹画布
- 核心指标卡
- 姿态/坐标卡
- 快捷控制栏

示意：

```text
IMU Monitor                         ● 已连接
IMU解算 | 20 Hz | 包: 1024

┌──────────────────────────────────────┐
│                                      │
│          局部 ENU 轨迹画布            │
│     蓝色轨迹线 + 绿色当前点 + 航向箭头 │
│                                      │
└──────────────────────────────────────┘

速度 1.24 m/s     累计距离 38.6 m
航向 126.4°       质量 96%

East 12.42 m      North -4.88 m
Roll 1.2°         Pitch -0.8°      Yaw 126.4°

[开始]        [暂停]        [记录]        [清空]
```

### 2.3 地图页

地图页用于真实电子地图展示，适合有经纬度数据时现场查看实际位置。

地图页保持极简，只显示地图和少量关键信息，不放复杂表格和设置。

内容组成：

- 顶部悬浮状态条
- 真实地图
- 当前定位点
- 地图轨迹线
- 自动跟随当前点
- 底部关键信息条

示意：

```text
● 已连接 | 20 Hz | 包: 1024

┌──────────────────────────────────────┐
│                                      │
│              真实电子地图             │
│        轨迹线 + 当前点 + 自动跟随      │
│                                      │
└──────────────────────────────────────┘

速度 1.24 m/s   距离 38.6 m   航向 126°
```

地图页规则：

- 有经纬度数据时显示真实地图轨迹。
- 没有经纬度但有 ENU/IMU 局部轨迹时，使用设备页配置的参考原点把 ENU 转为 WGS84 经纬度后显示到地图。
- 完全没有轨迹数据时显示空状态。
- 地图页不承担连接配置、算法选择、日志查看等调试职责。

### 2.4 设备页

设备页负责连接、模式、算法和日志。

内容组成：

- 连接状态摘要
- TCP 连接设置
- 协议与工作模式
- 运行日志列表

示意：

```text
设备状态
● 已连接
192.168.16.254:8000
接收中 | 20 Hz

连接设置
通信方式    TCP Client
Host        192.168.16.254
Port        8000
协议        IMU CSV
[连接 / 断开]

工作模式
[IMU 解算] [位置直显]
算法版本    v1_matlab_port

运行日志
08:42:01 连接成功
08:42:03 开始接收数据
08:42:04 当前频率 20 Hz
```

## 3. 数据对象映射

桌面端已有核心数据对象，手机端按同样概念简化。

### 3.1 AppStatus

用于更新顶部状态条和设备状态摘要。

```text
connectionState: 未连接 / 已连接 / 运行中 / 暂停 / 错误
mode: IMU 解算模式 / 位置直显模式
dataRateHz: 当前数据频率
packetCount: 包计数
message: 当前运行状态
running: 是否运行中
```

### 3.2 TrackPoint

用于轨迹绘制和状态展示。

```text
latitude / longitude / altitude
east / north / up
velocityE / velocityN / velocityU
speed
roll / pitch / yaw
source
quality
```

### 3.3 ImuSample

用于调试、协议解析和后续详情页。

```text
ax / ay / az
gx / gy / gz
mx / my / mz
temperature
packetId
```

## 4. 视觉风格

延续桌面端工业浅色风格，手机端更紧凑。

```text
页面背景: #EEF3F8
卡片背景: #FFFFFF
边框颜色: #D9E1EC
主蓝色:   #1D6FE9
运行绿:   #0A9F4D
告警红:   #D92534
正文色:   #172033
弱文字:   #768398
```

设计原则：

- 轨迹页优先保证现场可读性。
- 数据卡片不堆太多文字，重点突出速度、距离、航向、质量。
- 设备页允许信息密度稍高，用于调试。
- 日志使用等宽字体或紧凑列表，最多保留最近 100 条。

## 5. 迭代版本规划

## V1: 静态界面与本地轨迹画布

### 目标

先把手机端的界面骨架搭起来，完成“轨迹”和“设备”两个基础导航页与轨迹画布，不接真实设备。

### 功能范围

- MainActivity 使用底部导航：
  - 轨迹
  - 设备
- V1 暂不实现“地图”页，地图作为 V4 独立导航页加入。
- 轨迹页：
  - 顶部状态条
  - 局部 ENU 轨迹画布
  - 核心指标卡
  - 姿态/坐标卡
  - 开始、暂停、记录、清空按钮
- 设备页：
  - TCP Host/Port 输入框
  - 协议选择
  - 工作模式选择
  - 算法版本选择
  - 日志列表
- 使用模拟数据生成轨迹点，验证轨迹绘制效果。

### 技术范围

- Java 原生 Android 实现。
- 自定义 `TrajectoryView` 继承 `View` 绘制轨迹。
- 暂时不接 TCP。
- 暂时不实现完整导航算法。
- 使用 Handler/Timer 每 100 ms 生成一个模拟 TrackPoint。

### 验收标准

- App 能正常启动。
- 底部可以在“轨迹”和“设备”之间切换。
- 轨迹页能看到模拟轨迹线持续增长。
- 当前点、航向箭头、速度、距离、Yaw 能随模拟数据变化。
- 点击“清空”后轨迹和状态重置。

## V2: TCP 接入与协议解析

### 目标

让手机端可以连接 IMU 模块或桌面端同格式数据源，实时接收并解析数据。

### 功能范围

- 设备页 TCP Client 连接：
  - Host
  - Port
  - 连接/断开
- 协议支持：
  - IMU CSV
  - Position CSV
- 接收数据后更新：
  - 数据频率
  - 包计数
  - 日志
  - 当前原始 IMU 数据
  - 轨迹点
- 错误处理：
  - 连接失败
  - 断线
  - 空数据
  - 解析失败

### 技术范围

- 新增 TCP Client 后台线程。
- 新增按行拆帧逻辑，类似桌面端 `FrameBuffer`。
- 新增 CSV Parser：
  - `ImuCsvParser`
  - `PositionCsvParser`
- V2 可以先用简化算法：
  - Position CSV 直接生成 TrackPoint。
  - IMU CSV 先用于原始数据显示和日志，轨迹可以继续用简化积分或占位转换。

### 验收标准

- 输入正确 Host/Port 后可以连接。
- 收到数据后状态从“未连接”变为“已连接/运行中”。
- 数据频率和包计数会实时变化。
- Position CSV 可以直接绘制轨迹。
- 协议错误不会闪退，会写入日志。

## V3: 完整手机端监控闭环

### 目标

完成手机端第一版实用闭环：连接、运行、轨迹、状态、日志、记录。

### 功能范围

- 轨迹页控制按钮真实生效：
  - 开始
  - 暂停
  - 记录/停止记录
  - 清空
- 记录功能：
  - 记录接收到的原始文本行
  - 或记录 TrackPoint CSV
  - 文件保存到 App 私有目录或 Downloads
- 轨迹显示增强：
  - 自动跟随当前点
  - 自动缩放到当前轨迹范围
  - 比例尺
  - 无数据状态
- 状态展示增强：
  - 经纬度/高度
  - East/North/Up
  - Roll/Pitch/Yaw
  - Ve/Vn/Vu
  - 质量百分比
- 日志增强：
  - 最近 100 条
  - 支持清空日志
  - 不同类型日志区分：INFO / WARN / ERROR

### 技术范围

- 建立统一状态管理：
  - ConnectionState
  - RuntimeState
  - AppStatus
  - TrackPoint 列表
- UI 更新统一回到主线程。
- 轨迹点列表限制最大数量，例如 5000 点，避免手机内存持续增长。
- 保存记录时注意 Android 存储权限和系统版本差异。

### 验收标准

- 现场连接设备后，可以长时间稳定显示轨迹。
- 暂停后轨迹不再追加，但连接可以保持。
- 清空后轨迹、距离、状态归零。
- 记录文件能生成并可导出。
- 日志可以帮助定位连接和解析问题。

## V4: 独立地图页与工程化完善

### 目标

在 V3 稳定后，新增独立“地图”导航页，补充电子地图显示、配置持久化和整体工程质量。

### 功能范围

- 底部导航从两个页面扩展为三个页面：
  - 轨迹
  - 地图
  - 设备
- 新增地图页：
  - 顶部悬浮状态条。
  - 真实电子地图。
  - 当前点。
  - 经纬度轨迹线。
  - 自动跟随当前点。
  - 底部关键信息条：速度、距离、航向。
- 地图页状态：
  - 有经纬度时显示地图轨迹。
  - 无经纬度但有 ENU/IMU 局部轨迹时，使用参考原点进行 ENU -> WGS84 换算后显示地图轨迹。
  - 完全无轨迹数据时显示空状态。
- 设置持久化：
  - Host
  - Port
  - 协议
  - 工作模式
  - 算法版本
  - 地图参考原点：纬度、经度、高度
- 增加详情页或折叠面板：
  - 最近 IMU 原始数据
  - 最近 TrackPoint 数据
- 稳定性：
  - 后台线程关闭完整
  - 旋转屏幕不丢状态
  - 断线自动提示
  - 大量数据下不卡顿

### 技术范围

- 地图可选方案：
  - 高德 Android SDK
  - Android WebView + 高德/Leaflet 页面
- 第一优先级使用高德 Android SDK：在 `AndroidManifest.xml` 配置 Android Key，并用 `MapView` 原生绘制轨迹线和当前点。
- 坐标换算必须与桌面端一致：WGS84 数据转 ENU 用于局部轨迹，ENU/IMU 数据用参考原点转回 WGS84 用于地图显示。
- 使用 SharedPreferences 保存设置。
- 如需更强状态保持，可引入 ViewModel；若坚持 Java 原生，也可用单例状态仓库先实现。

### 验收标准

- 重启 App 后保留上一次连接配置。
- 底部导航包含“轨迹 / 地图 / 设备”三个页面。
- 有经纬度数据时可以在地图上看到轨迹。
- ENU/IMU 局部轨迹设置参考原点后，也可以在地图页看到对应轨迹。
- 无轨迹数据时地图页显示明确空状态，局部轨迹页仍可正常使用。
- 长时间运行不会明显卡顿或内存异常。
- Android Studio 无关键错误，Debug APK 可安装运行。

## 6. 推荐实现顺序

```text
V1: 先把界面和模拟轨迹做出来
V2: 接 TCP 和协议解析
V3: 补齐运行控制、记录、日志和状态闭环
V4: 再加地图、持久化和稳定性
```

不建议第一版就做地图 SDK、USB 串口或完整算法迁移。手机端第一阶段应该先证明链路可用：数据进来、轨迹出来、状态能看、日志能查。地图页等到 V4 再作为独立页面加入，避免轨迹页变得臃肿。

## 8. 版本完成后的效果

V1 完成后，App 看起来像真正的手机端 IMU 监控器，但跑的是模拟数据。

V2 完成后，App 可以接真实 TCP 数据。

V3 完成后，App 可以用于现场测试和记录。

V4 完成后，App 拥有“轨迹 / 地图 / 设备”三个清晰页面，接近完整手机端产品形态。
